

# Pac-Man

## Description

A Python remake of the 1980 arcade classic, built with `pygame-ce`.

Pac-Man runs through a maze, eats pacgums and is chased by four ghosts with different
personalities. Eating a super-pacgum frightens the ghosts and makes them edible for a
few seconds. The game runs for at least ten levels; each level has a time limit and the
score carries over. When the player loses the last life, wins the game or runs out of
time, the result is stored in a persistent top-ten table.

Two things make this project different from a plain Pac-Man clone:

- **The mazes are not ours.** Every level is generated by an A-Maze-ing package written
  by another team; our code adapts to its interface, never the other way round.
- **Game logic is completely separated from rendering.** The engine exposes one
  immutable snapshot per frame and never imports `pygame`, so all rules can be tested
  without opening a window.

- Python 3.14+
- [uv](https://docs.astral.sh/uv/) for dependency management
- Dependencies: `pydantic`, `pygame-ce`, and the assigned `mazegenerator` wheel

```bash

uv run pac-man.py config.json
```


### Cheat mode

Cheats exist for peer review, so the reviewer can reach every feature quickly.
All of them are toggles except _level skip_ and _extra life_, which are single actions.

| Key | Cheat                                                                       |
| --- | --------------------------------------------------------------------------- |
| `G` | invincibility — ghosts no longer kill, eating frightened ghosts still works |
| `T` | infinite time — the level timer stops counting down                         |
| `0` | slow ghosts                                                                 |
| `1` | +1 life                                                                     |
| `L` | skip the current level                                                      |

## Configuration

The game is launched with a JSON configuration file. In addition to standard JSON, any
line whose first non-blank character is `#` is treated as a comment and ignored.

| Key                                  | Default           | Valid range         | Meaning                                                              |
| ------------------------------------ | ----------------- | ------------------- | -------------------------------------------------------------------- |
| `highscore_filename`                 | `highscores.json` | any path            | where the top-ten table is stored                                    |
| `lives`                              | `3`               | 1–10                | starting lives                                                       |
| `difficulty_level`                   | `2`               | 1–3                 | ghost speed as a fraction of Pac-Man's: 1 → 0.5×, 2 → 0.7×, 3 → 0.9× |
| `points_per_pacgum`                  | `10`              | 5–20                | score for one pacgum                                                 |
| `points_per_super_pacgum`            | `50`              | 25–100              | score for one super-pacgum                                           |
| `points_per_ghost`                   | `200`             | 100–500             | score for eating a frightened ghost                                  |
| `level_max_time`                     | `90`              | 30–180              | seconds per level                                                    |
| `levels`                             | 10 generated      | at least 10 entries | list of level definitions                                            |
| `levels[].width` / `levels[].height` | `20`              | 10–50               | maze size in cells                                                   |
| `levels[].seed`                      | `null`            | int or `null`       | `42` for the first level, `null` (random) for the rest               |

Example:

```json
# General game settings
{
    "highscore_filename": "highscores.json",
    "lives": 3,
# Ghost speed: 1 (slow) to 3 (fast)
    "difficulty_level": 1,
    "level_max_time": 90,

# The first level has a fixed seed; null means random generation
    "levels": [
        { "width": 21, "height": 21, "seed": 42 },
        { "width": 23, "height": 21, "seed": null }
    ]
}
```

### Faulty configuration handling

The parser never raises a traceback. Every problem is reported and the game continues:

- **missing key** → default value, message printed;
- **wrong type or out-of-range value** → default value, message printed;
- **unknown keys** → silently ignored;
- **fewer than ten levels** → the list is padded with default levels;
- **first level seed** is forced to `42`, later seeds are forced to `null`, so level one
  is always reproducible;
- **unreadable file, invalid JSON, wrong encoding, path that is not a file** → a single
  clear error message on stderr.

## Highscore

The table is a plain JSON list stored at `highscore_filename`:

```json
[
  { "nickname": "WAKA WAKA", "score": 128740 },
  { "nickname": "xD", "score": 87150 }
]
```

Rules:

- top **10** entries, sorted by score descending;
- nickname is 2–10 characters; longer input is truncated;
- scores are non-negative integers;
- the table is read when the highscore screen or the game start needs it, and rewritten
  after a game ends;
- entries that fail validation are skipped instead of breaking the file.

**Why this design.** A flat list of objects is the simplest thing that survives being
opened by a human, diffed by git and validated by pydantic without a schema wrapper.
Saving appends the new entry, sorts and truncates to ten, which removes all the special
cases that a "is this better than the last one?" comparison keeps getting wrong: an
empty file, a table with fewer than ten rows, and a tie with the last place.

## Maze Generation

Levels are generated by the assigned **A-Maze-ing package** (`mazegenerator 2.1.0`),
used as-is and installed from the wheel in the repository root. Everything that touches
it lives in one module, `src/core/maze_adapter.py`, so a new version of the package can
only ever break one file.

**What the package returns.** `MazeGenerator(size=(width, height), perfect=False, seed=…)`
produces `maze`, a `list[list[int]]` of cells, where each cell is a bitmask of its walls:
north `1`, east `2`, south `4`, west `8`; a set bit means a closed wall. `perfect=False`
is required: it leaves loops in the maze, and without loops there is nowhere to run from
the ghosts. Cells with value `15` are the isolated "42" block the package draws in the
centre.

**What the adapter does.**

1. Normalises the seed: `null` in the config becomes a random positive integer drawn from
   our own random generator, so level one (seed `42`) stays reproducible while later
   levels differ on every run.
2. Calls the package, capturing its console output, and converts any exception into a
   single `MazeError` with a readable message.
3. Validates the result: a list of lists, the requested dimensions, values within 0–15.
4. Expands the `W×H` cell grid into a `(2W+1)×(2H+1)` **tile grid** of `"wall"` and
   `"floor"`: cell `(x, y)` becomes the floor tile `(2x+1, 2y+1)`, and a cleared wall bit
   opens the tile between two neighbouring cells. Neighbouring cells share the wall tile
   between them. Cells of the "42" block become walls.

The package reseeds the global `random` module on every generation, so the game keeps its
own `random.Random()` instances for ghost behaviour.

## Implementation

**Movement.** Pac-Man and the ghosts always sit on a tile and carry `progress ∈ [0, 1)`
toward the next one. Speed is in tiles per second and every step is
`progress += speed * dt`, so the game runs identically at any frame rate. Direction
changes happen only at tile centres; a pressed key is buffered and applied at the first
junction where it fits, while pressing the opposite direction reverses immediately.

**Ghosts.** All four share one movement implementation and differ only in the target they
aim at: Blinky targets Pac-Man, Pinky 8 tiles ahead of him, Inky 8 tiles behind, Clyde
chases while far away and retreats to his corner when close. The direction is chosen by a
breadth-first search from the ghost's tile that carries the _first step_ of each path, so
the ghost always takes the first move of a shortest route. U-turns are excluded unless the
ghost stands in a dead end. In `frightened` mode the choice becomes random; in `eaten`
mode the ghost returns home and waits before rejoining the chase.

**Game rules.** `Game.update(dt, intent)` advances one frame: level timer, Pac-Man,
pacgums, ghosts, collisions, end-of-level check. Collisions are measured as a distance of
less than half a tile between sprites, which also catches two entities swapping places in
a single frame. Statuses are `countdown`, `playing`, `dead`, `level_won`, `game_over`,
`victory` and `pause`; the engine sets them, while the presentation layer plays its
animation and calls `end_countdown()`, `respawn()` or `next_level()` when it is done.

**Testing.** Pure logic is covered by pytest without a window: maze adapter, tile helpers,
player movement, highscore storage. Behaviour that needs many frames (chases, collisions,
status transitions) was verified with scenario scripts on real generated mazes.

## General Software Architecture

```
src/
├── main.py              entry point: parse arguments, load config, start the window
├── parsing.py           configuration loading and validation  (Config, ParsingError)
├── shared_types.py      the contract: Grid, Pos, Direction, GameStatus, GameState views
├── highscore.py         top-ten storage                        (HighscorePlayer, TopTen)
├── game.py              rules and state machine                (Game)
├── core/                engine, never imports pygame
│   ├── maze_adapter.py  A-Maze-ing package → tile grid         (build_grid_for_level)
│   ├── world.py         grid helpers: tile_at, neighbor, can_move, find_start,
│   │                    find_target, place_pacgums
│   ├── player.py        Pac-Man movement                       (Player)
│   └── ghosts.py        ghost AI                               (Ghost, Blinky, Pinky,
│                                                                Inky, Clyde)
└── visuals/             presentation, the only place importing pygame
    ├── visualiser.py    window, main loop, scene switching
    ├── event_handler.py keyboard and mouse → intents and cheats
    ├── maze_view.py     walls, pacgums, super-pacgums
    ├── entity_view.py   Pac-Man and ghost sprites with animation
    ├── hud_view.py      score, lives, level, time
    ├── menu_view.py / highscore_view.py / victory_view.py / countdown_view.py / controls_view.py
    └── game_layout.py   tile size and offsets for the current window
```


**Per-frame data flow.**

```
keyboard ──► event_handler ──► Game.update(dt, intent) ──► core (player, ghosts, world)
                                        │
                                        ▼
                              Game.snapshot() ──► GameState (frozen) ──► views ──► screen
```

`GameState` carries the grid, a view of Pac-Man, views of the ghosts, the pacgum sets,
score, lives, level and status. Views only read it, which is what keeps the engine
testable without a display.
